The comment is correct: the expression subtracted dropped **frames** from the retained **frames**, so on a shared frame where one observation lost, the winner's frame was removed from the expectation too and nothing required its observed row. The response of 22:45 claimed that every retained observation is checked; that claim was not true of the assertion and is withdrawn.

## Change

| Comment | Resolution | Where |
|---|---|---|
| **[P2]** Retained-observation assertion projected to frames too early | The check is now `check_retained(rows, raw_rows, dropped, group)` in a support module `tests/refine/_dedup_checks.py`. It works in raw-observation space first: `original` (the group's `(raw_id, frame)` rows), `dropped <= original`, `retained = original - dropped`; then it asserts that no two retained observations share a frame (so the accounting cannot leave two competing rows) and that every retained frame is an **observed** (`interp == 0`) output row; a filled row does not count. `_check_evening` calls it. | Task 9, Step 1a and `_check_evening` |
| Test the checker | `tests/refine/test_dedup_checks.py` has six tests that need no data and always run: the winner observed passes; the winner's observed row missing fails (the false pass the reviewer reproduced); only a filled row on the winner's frame fails; two retained observations on one frame fail; a dropped row not in the input fails; raw rows outside the group are ignored. The real-data module skips as a whole when the clips are absent, which is why the checker lives elsewhere. | Task 9, Step 1a |

I extracted the checker and its tests from the plan text and ran them in a scratch directory: 6 passed. That runs the checker only; it does not run the real-data tests or any of the feature.
