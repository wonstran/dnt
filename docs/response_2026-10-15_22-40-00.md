# Response to the review of the vehicle re-classification design

Design: [2026-10-15-vehicle-reclass-design.md](superpowers/specs/2026-10-15-vehicle-reclass-design.md) (now rev. 2)  
Review: [review_2026-10-15-22-04-16.md](review_2026-10-15-22-04-16.md)

All five findings and the three additional comments are accepted. I checked each against the code before
changing the design:

- `refine.io.to_work` reads the flag from either `r3` or `interp`.
- `FrameReader.frames()` raises and ends on a failed read.
- `VLMConfig.resolve()` applies the endpoint chosen by `use`, and the VLM rules live only in
  `RefineConfig.validate`.
- `TrackRefiner` closes its runner in `finally`.

I re-ran three of the review's probes: the 95th percentile of nine 100 px sizes and one 1,000 px size is 595 px
(820 px for five sizes), `read_csv` raises `EmptyDataError` on an empty file, and the current `ReClass` sort
picks frame 9 from equal-area rows `[9, 1, 5]`.

## Changes

| Comment | Resolution | Where |
|---|---|---|
| **[P1] 1.** Filled rows are not recognized after reading a headerless file | A row is filled when **either** `r3 == 1` or `interp == 1`, compared after `pd.to_numeric(errors="coerce")`. That covers a headerless file read with `TRACK_FIELDS` names, the named table from `interpolate_tracks_rts`, and a table holding both names. The rule already lives in `refine.io.to_work`. It moves into `filled_mask(df)` in `refine/io.py`, which both call, so the two cannot drift apart. The returned and written table keeps exactly the input's columns. New tests: a named interpolated DataFrame and the headerless file written from it give the same `cls` and `decisions`; both names present; an all-filled track goes to the fallback. | §4 step 2, §8, §9 |
| **[P2] 2.** The 95th percentile does not stop a single outlier | The percentile is replaced. `size` is now the `hv_min_count`-th largest `max(w, h)` over real rows (new parameter, default 3), so a track is flagged heavy only when at least that many real rows reach `hv_size`. Up to `hv_min_count - 1` outliers can never flag a track, whatever its length. A track with fewer real rows than `hv_min_count` is never flagged. It keeps car, bus and truck as options, and layers 2 and 3 decide it. The spec explains why this errs toward not flagging: a missed flag only loses the narrowing, while a false flag forces a wrong class. Tests cover 1, 2, 5, 10 and 20 real rows with an outlier far above the threshold, plus the at-threshold case. | §3, §5.1, §6, §9 |
| **[P2] 3.** Reading stops after an unreadable sample | The shared helper asks `FrameReader` for one frame per call on the same open reader and catches `ValueError` per frame. `FrameReader` keeps its position between calls, so it still decodes forward over short gaps, and after a failure it seeks on the next call. `FrameReader` is unchanged, so its existing callers stay strict. An unread frame leaves *n* only for the tracks that sampled it. VLM crop reads use the same helper; a failed crop is skipped and the tile uses the crops that were read. The regression fails a middle frame shared by two tracks and checks that later frames are still read. | §5.2, §5.3, §7, §9 |
| **[P2] 4.** The VLM config is not resolved and validated before preflight | The VLM rules move out of `RefineConfig.validate` into `vlm_problems(vlm) -> (problems, resolved)` in `refine/config.py`. `RefineConfig.validate` calls it with the same messages. `VehReClass` works on a deep copy: validate and resolve, then raise `ValueError` if the resolved backend is `none`, then run `check_vlm_dependencies` and `resolve_api_key` on the **resolved** copy, and only then build the detector. A supplied config that resolves to no backend is rejected rather than silently disabling layer 3, because `vlm=None` is already the off switch. Tests, all without network: a named `openai_compat` endpoint under top-level `none` is accepted, an unknown `use` is rejected, `votes=0` is rejected, `none` is rejected, the caller's object is unchanged, and `RefineConfig.validate` gives the same messages as before. | §3, §7, §8, §9 |
| **[P2] 5.** An empty track file fails before columns are named | `VehReClass` catches `EmptyDataError` at its own boundary and uses an empty `TRACK_FIELDS` table. `read_track` is unchanged. **The missing-video check comes first**, even for empty input, so a wrong path in a batch is not hidden by an empty file. Tests feed an empty DataFrame and a zero-byte file, each with `out_file` set. They check for a zero-byte output and empty `decisions`, and check the file size rather than calling `read_track` on the output. | §4 steps 0–1, §7, §9 |
| Runner ownership | Each `re_classify` call builds its own backend and `VLMRunner`, and closes it in `finally`, as `TrackRefiner` does. `vlm.max_calls` is therefore a budget per call, and a fatal error does not carry over into the next call. Nothing is built when no track reaches layer 3. A `budget` verdict falls back with a warning. Tests check that the runner is closed when `ask_many` raises and that a second call gets a fresh budget. | §5.3, §7, §9 |
| Constructor validation | `hv_min_count`, `num_frames` and `vlm_crops` must be integers ≥ 1 and `min_gap` an integer ≥ 0. Neither `bool` nor floats such as `10.0` are accepted as integers. `hv_size` must be None or finite and > 0. Every broken rule is listed in one `ValueError`. Tests include `vlm_crops=0`, `num_frames=10.0`, `hv_min_count=True` and `hv_size=inf`. | §3, §9 |
| Legacy sampling | `ReClass` keeps its own selection code (`sort_values` by area, then `head`) unchanged, and shares only the batched detection. The spaced, earlier-frame-wins rule is used by `VehReClass` alone. A regression pins the tie: rows `[9, 1, 5]` with `num_frames=1` still give frame 9. | §8, §9 |

## One change of my own

While resolving comment 4, I found that `VLMConfig` already has `min_conf` (default 0.7), which `refine` uses
for the same purpose. The separate `vlm_min_conf=0.6` parameter is removed, and layer 3 uses `vlm.min_conf`.
That leaves one confidence threshold per VLM config instead of two that could disagree. The default rises from
0.6 to 0.7. Pass `min_conf=0.6` in the `VLMConfig` to keep the old value.
