Both points are accepted. Both are fixed in `tools/golden_cases.py` and covered by unit tests in `tests/test_golden_tooling.py` that run without a clip.

---

1. **Medium: the recorded defects-file hash was never checked.** **Accepted.**

   - **New `check_manifest_defects(manifest, defects_path)`.** It raises `ValueError` if the SHA-256 of `known_baseline_defects.yaml` differs from `manifest["defects_file_sha256"]`. The message names both hashes and says to regenerate the golden outputs after a reviewed change.
   - **Where the golden test calls it:**
     - in `test_environment_matches_recorded_environment`, before any case is compared
     - again at the start of the exempted-track branch of `test_tracks_byte_identical`, so an exemption is never accepted against a defects file other than the one the golden outputs were generated with
   - **What this closes:** the check hashes the whole file, so it catches edits to `exception_type`, `message_regex`, `raised_at`, `root_cause` or the review metadata even when the evidence file is untouched.
   - **New unit test, `test_manifest_detects_metadata_only_change`:**
     1. It records the file hash in a manifest, and the check passes.
     2. It changes only `reviewed_by`, leaving the evidence file as it was.
     3. It confirms the file still passes `load_defects`, but that `check_manifest_defects` now raises.
   - **Docs:** the YAML header comment and Task 21 now state that any edit to the defects file requires regenerating the golden outputs.

2. **Medium: evidence could point outside the reviewed traceback directory.** **Accepted.**

   - **`load_defects` now confines evidence paths.** It rejects absolute paths, then resolves `root / evidence`, which normalises `..` and follows symlinks, and requires the result to be inside `root / tests/golden/defects` (`Path.is_relative_to`). Only after that does it check that the file exists and compute `evidence_sha256`.
   - **Error message:** "evidence must be a repo-relative path inside tests/golden/defects/".
   - **New invalid cases in `test_invalid_defect_entries_rejected`:**
     - `README.md`, a file that exists in the repository but outside the directory
     - `tests/golden/defects/../../../README.md`, a `..` traversal
     - `/etc/hostname`, an absolute path
   - **New `test_symlink_escaping_evidence_dir_rejected`:** a link inside the directory that points at `README.md` is rejected.
   - **Docs:** the `Interfaces` block and the defects-file header comment describe the rule. The new `DEFECTS_DIR` constant is the single definition of the directory.
