# dnt 0.3.3: Correctness and Packaging (Sub-project A)

- **Status:** approved in brainstorming (Sections 1–6), awaiting written-spec review
- **Date:** 2026-09-23
- **Baseline:** dnt 0.3.2.4 (`063a9b5`)
- **Roadmap:** [`design/dnt-0.4-upgrade.md`](../../../design/dnt-0.4-upgrade.md). Where the two differ on anything in 0.3.3's scope, this spec takes precedence.

## 0. Context and agreed constraints

The dnt upgrade is split into six sub-projects, each with its own spec, plan, and implementation cycle:

| Sub-project | Scope |
|---|---|
| **A** | **0.3.3 correctness and packaging (this spec)** |
| B | Internal foundations |
| C | Dependency migration (BoxMOT 25, new Ultralytics) |
| D | Speed |
| E | Unified public API and tuning |
| F | New capabilities |

Constraints agreed during brainstorming:

1. **dnt has outside users who install it from PyPI.** Changes follow semantic versioning. 0.3.3 is a patch release, so the public API does not change. The only exception is that silent misbehaviour becomes a clear error. Detection and track files written by 0.3.x must keep loading.
2. **Tracker settings bug (B1).** User-set tracker settings must take effect. Users who never tuned anything must get **byte-identical** tracks, because the effective defaults stay BoxMOT's YAML defaults.
3. **B1 mechanism.** Overlay the user's settings on BoxMOT's own YAML defaults and pass the result as `evolve_param_dict`. Do not construct tracker classes directly in 0.3.3.
4. **Test data.** CI uses a synthetic video with a stub detector. Golden-file and benchmark tests use a local clip given by `DNT_REF_CLIP`, and the clip stays out of git.
5. **Environment-visible cleanups ship in 0.3.3:** removing unused dependencies, `requires-python >=3.11`, and removing the `sys.path` hacks.

**Goal:** a patch release in which dnt does what its documentation says, installs correctly from PyPI, and has a test safety net for sub-projects B–F.

**In scope**

6. Changelog, docs, and release preparation (§6).

**Out of scope** (deferred to B–F)

- Renames and the unified API.
- BoxMOT 25 and Ultralytics `quantize` / `nms`.
- Speed work.

- S3. For each tracker, an untuned dnt config produces the same argument dict as BoxMOT's YAML. On `DNT_REF_CLIP`, untuned tracks are byte-identical to 0.3.2.4.

## 2. B1: tracker settings reach BoxMOT (also B2 and the Tracker part of B8)

### 2.1 Root cause (verified against the BoxMOT 16.0.11 source)

`Tracker` filters its kwargs down to `signature(create_tracker)`, which is `(tracker_type, tracker_config, reid_weights, device, half, per_class, evolve_param_dict)`. That discards every tuning field. When `evolve_param_dict is None`, `create_tracker` loads `configs/trackers/<type>.yaml` and uses `{k: v["default"]}`. Otherwise it uses `evolve_param_dict.copy()` in its place. Either way, the resulting dict is passed as `tracker_class(**tracker_args)`.

All BoxMOT 16 tracker classes accept `**kwargs` and forward them to `BaseTracker(det_thresh, max_age, max_obs, min_hits, iou_threshold, per_class, nr_classes, asso_func, is_obb, **kwargs)`. `BaseTracker` also accepts `**kwargs`. As a result, **unknown names are ignored silently**, so dnt must validate them itself.

### 2.2 Config classes

- Every config becomes `@dataclass(kw_only=True)`: `MOTBaseConfig` and the 8 subclasses. Positional use (for example `BoTSORTConfig(ReIDWeights.X)`) now raises `TypeError`. **This fixes B2.**
- Every tuning field defaults to `None`, meaning "use BoxMOT's default". Each docstring states the effective value, for example "`track_thresh`: default `None` (BoxMOT 16: 0.6)".
- `model`, `per_class`, `reid_weights`, and `extra_kwargs` keep their current meaning and defaults.
- `from_dict`, `to_dict`, `export_yaml`, and `import_yaml` still work. YAML exported by 0.3.2.x loads. Its explicit numeric values are now treated as user-set, which is correct.

Fields and their effective defaults (BoxMOT 16 YAML):

| Config | Existing fields | Added fields |
|---|---|---|
| `ByteTrackConfig` | `track_thresh` (0.6), `match_thresh` (0.9), `track_buffer` (30), `frame_rate` (30) | `min_conf` (0.1) |
| `BoTSORTConfig` | `track_high_thresh` (0.6), `track_low_thresh` (0.1), `new_track_thresh` (0.7), `match_thresh` (0.8), `track_buffer` (30), `proximity_thresh` (0.5), `appearance_thresh` (0.25), `with_reid` (constructor default) | `cmc_method` ("ecc"), `frame_rate` (constructor default) |
| `OCSORTConfig` | `det_thresh` (0.6), `max_age` (30), `min_hits` (3), `iou_threshold` (BaseTracker default), `asso_func` ("iou"), `delta_t` (3), `inertia` (0.1) | – |
| `DeepOCSORTConfig` | `det_thresh` (0.5), `max_age` (30), `min_hits` (3), `iou_threshold` (BaseTracker default), `asso_func` ("iou"), `delta_t` (3), `inertia` (0.2) | – |
| `StrongSORTConfig` | `max_dist` → **renamed** `max_cos_dist` (0.4), `max_iou_dist` (0.7), `max_age` (30), `n_init` (3), `nn_budget` (100), `ema_alpha` (0.9), `mc_lambda` (0.98) | – |
| `HybridSORTConfig` | `det_thresh`, `max_age`, `min_hits`, `iou_threshold`, `asso_func` (BaseTracker defaults) | – |
| `BoostTrackConfig` | `det_thresh` (0.6), `max_age` (60), `min_hits` (3), `iou_threshold` (0.3), `asso_func` | – |
| `SFSORTConfig` | `det_thresh`, `max_age`, `min_hits`, `iou_threshold`, `asso_func` (accepted by BaseTracker) | `high_th` (0.6), `low_th` (0.1), `new_track_th` (0.7), `match_th_first` (0.67), `match_th_second` (0.3) |

"Constructor default" and "BaseTracker default" mean the key is not in BoxMOT's YAML, so the class signature default applies. That is exactly what happens today.

`StrongSORTConfig.max_dist` is still accepted as a deprecated alias. It emits `DeprecationWarning` and maps to `max_cos_dist`. Setting both raises `ValueError`.

**To verify during implementation:** whether SF-SORT reads the `BaseTracker` fields (`det_thresh`, and so on). If it does not, the `SFSORTConfig` docstring must say they have no effect on SF-SORT. Do not remove them in a patch release.

### 2.3 Building the tracker arguments

A new private function `_build_tracker_args(config) -> dict` in `track/tracker.py`:

1. `tracker_type = config.model.value`. Load BoxMOT's YAML defaults with the same code path BoxMOT uses: `get_tracker_config(tracker_type)` followed by `{k: v["default"]}`.
2. Collect the user values: the non-`None` tuning fields from `asdict(config)` (excluding `model`, `per_class`, `reid_weights`, and `extra_kwargs`), plus `extra_kwargs`. Then apply the renames (`max_dist`→`max_cos_dist`).
3. **Validate** each user key against the accepted parameters. The accepted set is `inspect.signature(TrackerClass.__init__)` together with `inspect.signature(BaseTracker.__init__)`, minus `{self, reid_weights, device, half, per_class, kwargs}`. The class comes from BoxMOT's `TRACKER_MAPPING`. A key outside the set raises `ValueError(f"{Config.__name__}: unknown BoxMOT parameter '{k}' for {tracker_type}. Valid: {sorted(valid)}")`. Keys that come from the YAML are **not** validated and are passed through unchanged, which keeps untuned behaviour identical.
4. Return `{**yaml_defaults, **user_values}`.

`Tracker` then calls `create_tracker(tracker_type=..., reid_weights=..., device=..., half=..., per_class=config.per_class, evolve_param_dict=_build_tracker_args(config))`. The current signature-filtering logic and the import-path fallback chain (`tracker_zoo` variants) are both replaced. The package requires `boxmot>=16.0.11,<17`, and `from boxmot import create_tracker` is the supported path in that range.

### 2.4 `update()` call

Remove the `except TypeError: tracker.update(dets, frame, None)` retry. A real `TypeError` raised inside `update` must propagate instead of re-running `update`.

### 2.5 Device and precision (the Tracker part of B8)

Extract the Detector's resolution logic (validate `{auto, cuda, xpu, mps, cpu}` with an optional `:N`; `auto` resolves as cuda → xpu → mps → cpu; an unavailable backend falls back to cpu) into the private `dnt/_device.py` as `resolve_device(device: str) -> str` and `half_allowed(device: str, half: bool) -> bool`. `half_allowed` is true only when the resolved device starts with `"cuda"`. `Detector`, `Segmentor`, and `Tracker` all call it.

`Tracker` then converts the resolved device to BoxMOT's format (`"cuda:N"` → `"N"`, `"cpu"` → `"cpu"`, `mps` passed through). The `CUDA_VISIBLE_DEVICES == "auto"` workaround is removed.

### 2.6 Tests (S2, S3)

These tests are parametrised over all 8 trackers. They use motion-only construction where possible. For ReID trackers, the ReID model is monkeypatched so that no weights are downloaded.

- Build each tracker with two non-default values, and assert them on the resulting BoxMOT object.
- An untuned config gives `_build_tracker_args(cfg) == yaml_defaults`.
- An unknown field raises `ValueError`.
- Positional arguments raise `TypeError`.
- `max_dist` emits a warning and maps to `max_cos_dist`. Setting both raises.

## 5. Tests and safety net

- **Layout:** `tests/` at the repository root. pytest is configured in `pyproject.toml` (`[tool.pytest.ini_options]`) with three markers: `model` (downloads real weights), `golden` (requires `DNT_REF_CLIP`), and `slow` (builds the wheel). By default only unmarked tests and `slow` tests run. `model` and `golden` are opt-in.

- **Fixtures** (`tests/conftest.py`):
  - `synthetic_video` (session scope). Written with `cv2.VideoWriter` (mp4v) at 320×240, 25 fps, 150 frames, with 3 filled rectangles on scripted paths:
    - object 1 is hidden for frames 60–67, which creates the interpolation gap
    - objects 2 and 3 cross between frames 90 and 110
    - the ground-truth paths are returned alongside the video
  - `stub_dets`. A detection file in `DET_FIELDS` layout built from the ground truth, with ±1 px noise (fixed seed), about 3% of detections dropped at random, and constant class 2 and conf 0.9.

- **Tests:**
  - **Unit:** every §3 fix, and every §2.6 case.
  - **Device resolution:** the device functions with `torch.cuda.is_available` etc. monkeypatched.
  - **Version** and **no-stray-modules** checks.
  - **CPU pipeline:** `stub_dets` → `Tracker(ByteTrackConfig())` and `Tracker(OCSORTConfig())`. Tracking needs a frame source, so these use the synthetic video. Then `interpolate_tracks_rts` must fill frames 60–67 for object 1's track, followed by `link_tracklets` and `Labeler.draw_tracks`. The output video must exist and have 150 frames.
  - **`model`:** `Detector(model="yolo26n")` on the synthetic video returns a DataFrame with `DET_FIELDS` and integer coordinates.
  - **`slow`:** `python -m build` into a tmp directory, then assert that the wheel contains the three `.names` files. A second test installs the wheel into a tmp venv and imports `dnt`.
  - **`golden`:** run only when `DNT_REF_CLIP` and `DNT_GOLDEN_DIR` are set. The golden outputs are produced **once** by `tools/make_golden.py`, run inside a git worktree of `063a9b5` (0.3.2.4). They cover:
    - detections from `Detector()` with default settings
    - untuned tracks for ByteTrack and BoT-SORT
    - `interpolate_tracks_rts` and `link_tracklets` via the DataFrame path, because the 0.3.2.4 file path has bug B3

    0.3.3 must reproduce detections and untuned tracks exactly, and the interpolate / link outputs exactly. If detection is non-deterministic on the GPU, the tolerance is documented in the test rather than loosened silently.
- **Benchmark:** `tools/bench.py --video PATH [--stages detect,track,post]` prints frames/s for each stage, peak CUDA memory, and wall time. It is run on 0.3.2.4 (from the worktree) and on 0.3.3, and the results are recorded in `docs/benchmarks.md`. This is the baseline for sub-project D.
- **CI:** `.github/workflows/ci.yml` runs:
  - `ruff check`
  - `pytest -m "not model and not golden"`, on Python 3.11, 3.12, and 3.13 with CPU torch (`--index-url https://download.pytorch.org/whl/cpu`)
  - a separate build-and-inspect-wheel job

  `site/` is left untouched in this release.
- **Environment first:** the project `.venv` was recreated empty (uv, Python 3.10) on 2026-09-23. The first step of the implementation plan rebuilds it with `uv venv --python 3.12 && uv pip install -e .[dev]`, **after confirming with the maintainer**.

## 7. Risks

| Risk | Mitigation |
|---|---|
| BoxMOT's YAML changes between 16.x patch releases, which would move the "untuned" defaults | The pin is `<17`. The S3 test compares against whichever YAML is installed, and the golden test catches drift on the reference clip. |
| A ReID tracker test downloads weights in CI | Monkeypatch the ReID backend. Any real-weight test is marked `model`. |
| GPU non-determinism breaks exact golden detections | Compare on the same GPU and precision. If that is still not exact, document a per-column tolerance in the test. |
| Users relied on a pruned dependency being installed transitively | The changelog lists every removed package. |
| B12 changes timestamps some users depend on | The semantics are confirmed before coding, and the changelog's *Important* section calls it out. |
