## Retry-budget decision (Tasks 4, 7, 9)

`max_calls` is now a **hard limit on backend invocations, retries included**. The earlier policy ("votes are budgeted, retries are free") allowed up to six invocations for one vote, as your six-invocation case shows.

- Admission is unchanged: whole questions, in priority order, each needing all its uncached votes.
- Whatever `max_calls` has left after admission becomes a **retry allowance**. It is a per-`ask_many`-call counter that all retries of that call draw from.
- A retry after a transient failure or an invalid reply takes one unit. If none is left, the question ends with `error="budget"` and stays pending. The check happens before the backoff sleep, so an exhausted allowance does not wait.
- A retry can never take a unit that an admitted question needs. `calls + retries <= max_calls` always holds, including across successive `ask_many` calls: later calls start from `max_calls - calls - retries`.
- Cost: with a tight budget there is no allowance, so a single transient failure leaves the event pending instead of retrying. I think that is the right trade for a cost cap, and it is documented in the Task 4 interface block.
- A question that runs out of allowance is counted in `budget_skipped`, not in `failures`.
- Tests:
  - Your six-invocation case: `max_calls=1` makes exactly one invocation.
  - For caps 2 to 5, `len(backend.calls) <= cap` and `calls + retries == len(backend.calls)`.
  - A multi-batch, concurrent run stays within the cap across stage calls.
  - A rewritten `test_retries_draw_only_from_what_admission_left_over`: with budget 3 the retry happens; with budget 2 it does not, and the other question is still answered.
  - End-to-end in `refine`: the same scene with `max_calls=2` retries and with `max_calls=1` stays pending with `vlm.error == "budget"`.
- Spec follow-up (Task 9) and Review Focus item 2 now state the hard limit instead of "retries are not billed".

- **Ownership** is proven only by a valid manifest. With none, cleanup removes the page and nothing else.
- Tests:
