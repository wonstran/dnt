## Comments

1. **[P1] Preserve unique observed rows when merging overlapping tracklets.** In `merge_chains` (plan lines 2693–2732), the later member loses *every* row at or before `prev_last`. Stage 3's overlap gate (lines 4466–4482) requires matching boxes only on shared frames, so it can accept A at frames `0–8, 11` and B at `9–12` when their frame-11 boxes agree (`g = -2`). The merge then deletes B's unique observations at frames 9 and 10 as well as the duplicate at 11. This contradicts design §6.3, which drops only overlapping rows from B. Drop rows whose frame is already present in the merged chain, and add a sparse-overlap test that asserts frames 9 and 10 remain observed.

2. **[P1] Do not suppress a whole-track screen event when every segment supports it.** `propose_screen` (plan lines 3957–3973) checks that all segment scores reach `reject_below`, but then uses the whole-track score `w`; if `w` is below the threshold, it emits no event. For example, a track with two long stationary segments at distant locations can score as static in each segment while its whole-track displacement makes the whole static score zero. Design §6.2 says the event should cover the whole track when every segment supports the hypothesis. Derive an eligible whole-track event score from the segment scores in this branch, and test the two-location case.

3. **[P1] Reject nonnumeric values in the remaining input columns.** `_read_numeric_csv` (plan lines 1609–1623) validates only the first six fields. `to_work` (lines 1632–1654) then converts a bad `score` or `cls` to `-1`, and a bad `r3` to an observed row. A malformed ten-column dnt file can therefore silently change class, confidence, or interpolation status instead of raising the file-and-line `ValueError` required by design §10. Validate every consumed field for each declared format, and add tests with bad `score`, `cls`, and `r3` values (including a filled-row flag).

4. **[P2] Align the P1 feature claim with what can be applied.** The goal and proposed API/changelog text (plan lines 5, 5814–5818, 5875–5881) say P1 splits ID switches and links occlusion-witnessed gaps. In the normal P1 path, motion-only switch scores are capped at 0.70 below the 0.90 accept threshold (lines 1965–1972, 3303); occluded links are capped at 0.75 below the 0.80 link threshold (lines 4570–4572 and config). Both become `HUMAN_PENDING` under `route_without_vlm` (lines 2900–2908), while the manual `apply` path is deferred to P4 (lines 23–26). P1 can propose these edits but cannot apply them. State that limitation in its public docs and changelog, or include a minimal decision/apply path in P1 before claiming those results.

Static review of the plan and approved design; no implementation tests were run.
