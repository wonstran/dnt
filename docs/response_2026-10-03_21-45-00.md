# Response to the review of the track dedup design

Spec: [2026-10-03-track-dedup-design.md](superpowers/specs/2026-10-03-track-dedup-design.md) (rev. 2)  
Review: [review_2026-10-03_21-13-21.md](review_2026-10-03_21-13-21.md)

All seven comments are correct. I checked each claim against the code before changing the spec: `proposal_key` hashes the lineage in the order given (`events.py`), `_Stages._orphans` receives only link's sets, `propose_orphans` counts observed rows divided by `fps`, and `review._output_ids` looks up `event.tracks` directly in `id_map`. The spec is revised; nothing was implemented, and none of the new rules has been run. They are specified and tested on paper only.

## Changes by comment

| # | Comment | Resolution | Where |
|---|---|---|---|
| 1 | **[P1]** `cooccur` denominator and zero-shared case undefined; 122/125 would score zero | Replaced the IoU-based `cooccur` with `co_occupancy = shared / min(n_a, n_b)`, defined over the span overlap, `0.0` when `shared == 0` (and `min(n_a, n_b) > 0` is guaranteed by the `min_observed` gate). 122/125 is `7/76 = 0.09`, below `cooccur_lo`. Signals record `shared`, `n_a`, `n_b`. The §1 table now lists span and `n` and notes that the 7 shared frames of 122/125 have IoU 0.00. Test 1 uses the real counts and shared-frame IoU; test 2 covers the formula including `shared = 0`. | §1, §3.2, §3.3, tests 1–2 |
| 2 | **[P1]** Fully co-observed overlapping parallel boxes would auto-merge | Occupancy is now an **occupancy gate**: `co_occupancy >= cooccur_hi` makes a pair not a candidate, whatever the boxes' IoU. `distinct_iou` is removed. Simultaneous duplicate detections (same frames, overlapping boxes) are declared out of scope and never merged. Test 4 is the reviewer's case (IoU 0.5 on every frame); test 5 covers a same-frame duplicate. | §2, §3.2, §6, tests 3–5 |
| 3 | **[P1]** Union-find can merge A/C against evidence or a rejection | Added a deterministic procedure: accepted edges sorted by `(-algo_score, proposal_key)`; an edge is skipped as `redundant` or `conflict` when joining would put a cannot-link pair in one component. Cannot-link pairs are: a rejected `MERGE` (auto, VLM or human; human rejections come from recorded decisions on re-run), a pair that fails the occupancy gate, and a class mismatch. A skipped edge stays accepted with `applied: false`, `skipped_reason` and `conflicts_with`, and counts in the summary. Test 7 covers dense and rejected A/C with shuffled order. | §3.5, §5, test 7 |
| 4 | **[P2]** Orphan pass not integrated with merges | `dedup` returns `merged_reps` and `pending_endpoints`. `_Stages` carries them through link, mapped by `rep_of`, and unchanged when `link.enabled` is false, then hands `linked | merged_reps` and `link_pending | pending_endpoints` to `_orphans`. Accepted merges protect their representative; pending merges defer the orphan drop and show in `orphan_deferred`. Test 11 covers both link settings and a link that absorbs the representative. | §3.6, test 11 |
| 5 | **[P2]** Key depends on work-ID order for equal-start pairs | The two lineage entries are sorted by their first raw span `(raw_id, f0, f1)` before hashing. Representative choice (`tracks` order) stays separate and does not enter the key. Test 13 renumbers work IDs while keeping raw IDs, with an equal-start pair whose work-ID order reverses. | §3.3, test 13 |
| 6 | **[P2]** Absorbed IDs do not resolve to output IDs | `_Stages` keeps an `absorbed` map composed across dedup and link; the header stores it fully resolved; `review._output_ids` uses `id_map[resolve(t)]`. This also fixes LINK cards whose endpoint another link absorbed, an existing gap in the same function (a small scope extension, called out in §5). The spec notes that dedup and link create no new IDs, so absorbed IDs are never reused. Test 14 is the reviewer's scenario: a pending pair whose endpoint is absorbed by a merge and then a link. | §3.1, §5, test 14 |
| 7 | **[P2]** `dropped_rows` attribution for multi-edge components | Rows are dropped when an applied edge joins two components, attributed to that edge. The row order is total (higher `score`, then smaller `raw_id`, then smaller `track`), so the final kept set does not depend on edge order. Redundant and conflicting edges own no rows (`dropped_rows: 0`). Each edge lists `dropped` as `[raw_id, f0, f1]` runs, so the ledger names the discarded observations. For the cyclic case, two edges join and drop two rows, and the third is redundant. Test 8 uses tied scores and shuffled proposal orders. | §3.5, test 8 |

## Other changes made while revising

- §1 now says which `n` values were measured. The `n` of 122/134 and 125/134 on the second track are marked "not measured" instead of invented. The plan's first task re-measures the whole table with the final code.
- Success criteria now include the cannot-link guarantee (criterion 4), the dropped-row accounting (criterion 3) and the overlapping-parallel case (criterion 2).
- Config: `distinct_iou` removed; `cooccur_lo` must be less than `cooccur_hi`.
- Summary: `summary["dedup"]` counts applied, redundant and conflicting edges and total `dropped_rows`.
