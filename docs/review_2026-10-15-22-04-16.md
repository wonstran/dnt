# Review: vehicle re-classification design

Reviewed: 2026-10-15 22:04:16 EDT  
Design: [2026-10-15-vehicle-reclass-design.md](superpowers/specs/2026-10-15-vehicle-reclass-design.md)

The cascade is specified clearly enough to assess, but the following contracts need correction before implementation. Findings are ordered by impact. P1 means a high-priority correctness issue; P2 means an issue to resolve during normal implementation planning.

## 1. [P1] Recognize the interpolation flag after reading headerless files

**Location:** §4, lines 83–87; §9, lines 220 and 230–231.

Reading a file and assigning `Tracker.TRACK_FIELDS` names gives column 8 the name `r3`, not `interp`. The proposed real-row check therefore treats every row of an interpolated track file as real. This is the normal pipeline format: `interpolate_tracks_rts` stores its flag in that same column and writes without headers. The same data would produce different classification evidence depending on whether the caller supplies its named DataFrame or its saved file.

Filled boxes would influence the heavy flag, consume sample slots, and cast votes. A track containing only filled rows would also miss the promised immediate fallback. Existing refinement code already recognizes both flag names: [io.py](../src/dnt/refine/io.py#L96), lines 96–115; see also [interpolate.py](../src/dnt/refine/interpolate.py#L333), lines 333–348.

**Requested change:** Define the evidence mask using both `interp == 1` and `r3 == 1`, including how to handle tables containing both names. Preserve the original columns in the returned/written table. Add parity tests that classify a named interpolated DataFrame and its headerless file, plus an all-filled file.

## 2. [P2] The 95th percentile does not provide the promised single-outlier protection

**Location:** §5.1, lines 103–107; §9, line 221.

With the usual NumPy/pandas percentile interpolation, nine sizes of 100 px and one glitched size of 1,000 px have a 95th percentile of **595 px**. At `hv_size=500`, that single bad box flags the track heavy. For five observations, the same outlier gives **820 px**. Short tracks are explicitly supported, so this contradicts both the stated reason for choosing the percentile and the proposed outlier test.

The consequence is stronger than a biased score: the heavy flag removes car from both re-detection and VLM options. Later accurate evidence cannot recover the car label, and fallback becomes truck.

**Requested change:** Specify the percentile method and a short-track policy that actually supplies the desired robustness, such as requiring multiple threshold-exceeding observations before applying the hard heavy restriction. Alternatively, weaken the claimed guarantee explicitly. Test the chosen behavior for 1, 2, 5, 10, and 20 real observations, with the outlier large enough to cross the threshold.

## 3. [P2] Specify how decoding continues after an unreadable sample

**Location:** §5.2, lines 116–120; §5.3, lines 145–147; §8, lines 198–206.

`FrameReader.frames()` raises `ValueError` on an unreadable requested frame or a failed intermediate `grab`; it does not yield a failure result and continue. Once that exception escapes, the generator is exhausted. Catching around a single `for` loop over the merged frame union therefore loses all later samples, including samples belonging to otherwise healthy tracks. This behavior is explicit in [crops.py](../src/dnt/refine/crops.py#L77), lines 77–106.

**Requested change:** Describe the recovery mechanism in the shared helper. For example, request one sorted frame at a time on the same reader and catch read failures per request, allowing the next request to seek after `_next` is reset. Alternatively, introduce an explicit tolerant reader mode while preserving existing callers' strict behavior. Apply the same policy to VLM crop reads. A regression must fail a middle requested frame, successfully read a later one, and check that only affected tracks lose that frame from `n`.

## 4. [P2] Resolve and validate the supplied VLM configuration before preflight

**Location:** §3, lines 56–58 and 75–79; §5.3, lines 151–155.

`VLMConfig` supports named endpoints through `use` and `endpoints`. A valid configuration can have top-level `backend="none"` while its selected endpoint supplies `backend="openai_compat"` and a model. Calling the named dependency/key helpers against the unresolved object checks the wrong backend. `check_vlm_dependencies` returns immediately for `none`, while `make_backend` rejects it. The refiner resolves the selected endpoint before backend setup; see [config.py](../src/dnt/refine/config.py#L340), lines 340–359, and [refiner.py](../src/dnt/refine/refiner.py#L688).

Also, the bare `VLMConfig` dataclass does not validate itself. Validation of backend/model, vote counts, timeouts, and endpoint settings currently lives in `RefineConfig.validate`. Reusing just `check_vlm_dependencies` and `resolve_api_key` does not reproduce that contract.

**Requested change:** Specify resolution and validation of a copied VLM configuration before dependency checks and detector construction. Define whether an explicitly supplied configuration resolving to `backend="none"` disables layer 3 or raises `ValueError`. Add tests for a selected named endpoint, an unknown endpoint, and invalid VLM settings, without network calls.

## 5. [P2] Handle empty track files before assigning column names

**Location:** §4, lines 83–84; §7, line 186; §9, line 231.

The path input flow delegates to `shared.files.read_track`, which directly calls `pandas.read_csv`. A zero-byte headerless file raises `pandas.errors.EmptyDataError`; it never produces the empty DataFrame needed by the promised empty-input behavior. Such files are legitimate outputs of stages with no retained tracks. An empty DataFrame test alone would miss this path-specific failure. See [files.py](../src/dnt/shared/files.py#L45), lines 45–65.

**Requested change:** Catch `EmptyDataError` at the new API boundary and build an empty table with `Tracker.TRACK_FIELDS`, or explicitly extend the shared reader's contract and test its callers. Include an empty-file input with `out_file` set, verify empty `decisions`, and specify whether empty input takes precedence over missing-video validation. Do not require `read_track` to read an empty output successfully unless its behavior is also changed.

## Additional contract and regression comments

- **Runner ownership:** §5.3 should state that the runner/backend is created for each classification run and closed in `finally`, or expose and document another lifecycle. `VLMRunner` owns a loop thread/client, and its budget counters and fatal-error state persist across `ask_many` calls. The existing refiner closes its runner per run ([refiner.py](../src/dnt/refine/refiner.py#L906)). Reusing a classifier should have an explicit budget/reset contract.
- **Constructor validation:** Include `vlm_crops` in §3's validation rules as an integer ≥ 1, and require integer sample/frame counts. Currently `vlm_crops=0`, fractional counts, and non-finite sizes are not covered by the stated rules or constructor tests.
- **Legacy sampling:** Protect `ReClass`'s existing sample selection when sharing helpers. Its current area-only sort does not use the new earlier-frame tie rule. With equal-area rows ordered `[9, 1, 5]` and `num_frames=1`, the existing implementation selects frame 9, whereas the proposed deterministic rule selects frame 1. Keep its legacy selection path if identical results are required, and include an area-tie boundary regression.

## Verification and limits

Reviewed the design against the current re-classifier, detector, track reader/writer, interpolation code, and VLM configuration/runner implementations. Ran local Python probes confirming the `r3` flag mapping, percentile examples, empty-file exception, reader-generator termination and successful recovery through a new request, named-endpoint resolution, and tied-area sample difference. These probes required no detector model or network access.

A separate runner-lifecycle probe was interrupted after it stalled and provides no runtime verification; that comment rests on inspection of the runner and refiner code. No production code or design text was changed, and the full test suite was not run for this document-only review.
