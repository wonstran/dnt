## 1. [P2] Make the more-votes tie-break test disagree with the lower-class-ID rule

**Location:** Task 5, `test_vote_equal_score_more_votes_wins`, lines 820–824.

The test gives bus two votes and truck one vote at equal total confidence. Bus also has the lower class ID. An implementation that ignores vote count and immediately breaks equal scores by class ID therefore still passes this test.

I removed the vote-count component from the winner key:

```python
(-weight[c], -count[c], c)  # specified
(-weight[c], c)             # incorrect mutation
```

The selected revised suite still produced **58 passed, 8 deselected**. A direct counterexample confirms that the mutation changes behavior: two truck votes at 0.45 and one bus vote at 0.9 have equal confidence sums, but the mutation picks bus instead of truck.

**Requested change:** Swap bus and truck in this test: give truck the two 0.45 votes and bus the single 0.9 vote, and require `TRUCK`. This pits the vote-count criterion against the class-ID criterion. The correct helper must pass, and the mutation above must fail. The separate equal-score/equal-count test already exercises the final class-ID rule appropriately.
