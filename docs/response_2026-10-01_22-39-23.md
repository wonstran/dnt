1. **P1: identify the actual DINO weights in the feature key.** **Accepted.**

   - **Cause.** `DinoEncoder.weights_sha` was `None` unless `encoder.weights` was set, so `facebook/dinov2-small` was keyed by its name alone.
   - **Fix (Tasks 1 and 3).** A new `encoders.parameters_digest(model)` hashes the loaded model's `state_dict` (names and float32 values). `DinoEncoder` computes it right after `from_pretrained`, before the model moves to a device, and stores it as `weights_sha`. It applies to a Hub name and to a local directory alike, so it describes what was actually loaded. The cache key already includes `weights_sha`. I chose the parameter digest over pinning a Hub revision: it needs no network call, works offline, and also covers a local directory that is edited in place.
   - **Spec.** §5.3 said "the SHA-256 of the weights file". A Hub model has no file path we control, so I amended that line to "a digest of the weights actually loaded (the weights file; for a Hub model the loaded parameters)". Nothing else in the spec changes.
   - **Tests.**
     - `test_dino_weights_sha_identifies_the_loaded_parameters` (Task 3): the same model name resolving to different weights gives a different `weights_sha`.
     - `test_parameters_digest_follows_the_weights_not_the_name` (Task 1).
     - `test_the_same_hub_model_name_with_new_weights_misses_the_cache` (Task 7): end to end, through the default encoder factory and a fake `transformers`; the second and third runs show a hit, then a miss after the weights change.
   - **Shared fakes.** The fake `transformers` and `torchreid` modules moved to `tests/refine/_fakes.py` so Tasks 3 and 7 use the same ones. They now carry a real `__spec__`, because `find_spec` raises on a module without one.

2. **P1: invalidate the memoized encoder when a local weights file changes.** **Accepted.**

   - **Cause.** `_encoder` memoized on the weights path, so a file replaced in place kept the old model, the old `weights_sha`, and therefore the old cache.
   - **Fix (Tasks 1 and 7).** A new `encoders.weights_identity(cfg, target)` returns the digest of the local file the encoder would load (`encoder.weights`, or the shipped OSNet file for `reid` pedestrians), else `None`. It is part of the memo key, so a changed file rebuilds the model and, through `weights_sha`, changes the cache key. It is skipped when the caller supplies an `encoder_factory`, which owns its own encoder.
   - **Limit, stated in the plan.** A running `TrackRefiner` does not re-resolve a Hub model name. A new refiner does, and the key then follows the loaded parameters (comment 1).
   - **Test.** `test_a_replaced_weights_file_reloads_the_encoder_and_misses_the_cache` (Task 7): one refiner, three runs; unchanged weights reuse the model and the cache (`loads == 1`, same key), then the file is rewritten at the same path (`loads == 2`, different key).
   - **Related hardening (Task 1).** The dependency check now treats an already-imported module whose `__spec__` is `None` as installed instead of letting `find_spec` raise `ValueError`.

3. **P1: treat structurally damaged feature archives as cache misses.** **Accepted.**

   - **Fix (Task 4).** `FeatureStore.load` validates before it returns a store. New helper `_well_formed` requires: `raw_id` and `frame` are 1-D integer arrays, `emb` is a 2-D float array, equal lengths, nonzero width when there are rows, all values finite, and no duplicate `(raw_id, frame)` pair. The `key` entry must be a 0-D string. Everything is read inside the exception handler, so a 0-D `raw_id` can no longer raise at `len()`. Loaded rows are cast to float32.
   - **Tests.** `test_readable_but_malformed_archives_are_misses` has 13 cases (1-D, string, wrong-row-count, zero-width, NaN and inf embeddings; 0-D, 2-D, float and string ids and frames; duplicate keys; a non-scalar or non-string key), plus a missing-array case and a control showing the helper writes a loadable archive.

4. **P1: recheck candidate eligibility after moving a split.** **Accepted.**

   - **Fix (Task 6).** `_relocate` takes an `eligible(row)` callback and only considers eligible rows. `_dense_rescore` handles each track's candidates in `_candidates`' priority order and builds the callback from the two rules `_candidates` applied:
     - each side of the cut keeps at least `switch.min_side_seconds` of clean samples (`_sides_ok`, using the same `_covered_seconds`);
     - the cut is at least `nms` frames from every other candidate, taken at its new frame if already placed and at its original frame otherwise.
   - **Why the original row is always a safe fallback.** Each placed candidate was checked against every other candidate's original frame, and the originals already satisfied both rules. So a candidate always has at least one eligible row, and no move can break either rule.
   - **Tests.**
     - `test_relocate_moves_to_the_best_eligible_row_and_stores_its_values` (unit): picks the best row, skips an ineligible best, falls back to the original row, and does nothing without dense samples.
     - `test_a_move_cannot_leave_too_little_clean_data_on_a_side`: the same data with `min_side_seconds` 0.5 moves the cut to frame 33, and with 1.5 keeps it at 30.
     - `test_converging_candidates_keep_the_nms_spacing`: cuts at 12 and 28 pull candidates at 10 and 30 to 16 frames apart with `nms=1`, and stay 20 apart with `nms=20`.

5. **P1: make the clipped-crop test agree with padded cropping.** **Accepted.**

   - **Cause.** The test expected the unpadded intersection (at most 25 x 40 pixels), but `crop_box` enlarges the box by 1.1 first.
   - **Fix (Task 2).** The test is now `test_crop_is_padded_then_clipped_to_the_frame` and asserts the real shapes: `(32, 43, 3)` for the clipped box and `(44, 66, 3)` for the same box away from the edges.
   - **Found while fixing it.** Two more problems in the same test and function.
     - `crop_box` used `floor`/`ceil` on the padded edges. For some sizes that adds or drops a pixel from float noise (`100 * 1.1 / 2` is `55.00000000000001`, so the left edge of a 100-pixel box comes out one pixel wider). The shapes in the test above happen to be exact either way, but crop sizes should not depend on that, so `crop_box` now uses `round` on the edges.
     - The "outside" case `(199, 99, 1, 1)` leaves a 2 x 2 crop, so it would not return `None`. It became `(200, 100, 5, 5)`, which leaves 0 pixels.
