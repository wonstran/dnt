# Review of the track refinement design

Reviewed: 2026-09-28 09:53 EDT  
Design: [2026-09-27-track-refinement-design.md](superpowers/specs/2026-09-27-track-refinement-design.md)

## Comments

1. **[High] Screen can discard a valid part of an ID-switched track before the switch stage runs.** Section 3 (lines 195–210) applies whole-track `DROP` events before `SPLIT`; §6.1 (lines 343–351, 381–390) scores in-vehicle and duplicate evidence over a track's lifetime. If an ID follows a pedestrian and then spends most of its frames on an in-vehicle passenger, a confident screen decision drops the pedestrian frames too. Stage 2 never gets the chance to separate them. Specify segment-aware screening, or defer destructive whole-track decisions when a switch candidate exists; test a mixed track with a real first segment and a false second segment.

2. **[High] A human-accepted split cannot receive downstream links on replay.** The pending split leaves the original track unchanged when stage 3 proposes links (§3, lines 195–210). Replay only applies the saved events and never proposes new ones (§4.2, lines 248–255). If a reviewer later accepts that split, its new tail has no corresponding `LINK` candidate, even if it should connect to another fragment. This affects the stated human review workflow and the hard-case objective. Define a way to regenerate downstream proposals after changed decisions, or retain conditional proposals for both split outcomes; add an integration test that accepts a pending split and then links its tail.

3. **[High] Stage 4 cannot be reused unchanged on a previously interpolated input.** The input contract says `interp == 1` rows stay unobserved (§2.5, lines 159–160), but the existing `interpolate_tracks_rts` treats every input row as an observation and sets each existing row's flag to 0 (`src/dnt/track/post_process.py`, lines 182–198 and 262–274). It can also smooth or fill using those synthetic rows. Section 6.4's direct call (line 521) would therefore relabel invented positions as observed, undermining the conflict and speed safeguards. Define an observed-only measurement path that preserves existing filled rows and their flags, and test a file that already contains `interp == 1` rows.

4. **[High] The protected occlusion gaps need an explicit interpolation API.** Section 6.4 (lines 521–525) says stage 4 uses `interpolate_tracks_rts` while excluding gaps from accepted occlusion-witnessed links regardless of `fill.max_gap`. The current function only accepts a global `max_gap` (`src/dnt/track/post_process.py`, lines 12–29 and 187–191); it has no exclusion spans and never reads a ledger. Specify the new parameter or a segmentation step, including how it behaves on replay and when multiple links form one track. Otherwise a larger `fill.max_gap` fills the 63-frame turn that §11.4 requires to stay empty.

5. **[Medium] Link verification can strand an otherwise valid second choice.** Section 6.3 (lines 502–508) creates an event only for the pair selected by Hungarian assignment. If that pair is rejected by the VLM or a human, the runner does not reconsider its second-best gated pair, so a recoverable fragmented trajectory remains fragmented. Specify whether assignment is rerun after rejected edges, or record alternatives for review and replay. Include a three-track fixture in which the highest-score pair is rejected and the next pair is correct.

6. **[Medium] The embedding cache can return features for a different video or context.** Sections 2.5 and 5.3 (lines 175 and 294–297) key `OUT.features.npz` by track-file hash and encoder settings. Crops come from the video, and the clean-crop mask depends on context boxes (§5.3, line 295). Reusing the same track CSV with a revised video or context file can silently reuse stale embeddings and change switch/link decisions. Include video and context identity, along with crop preprocessing settings, in the cache key; test cache invalidation when either changes.

7. **[Medium] Config validation contradicts the required no-video mode.** The default encoder is DINO (§9, lines 687–694), and config loading requires its extra (§9, line 770; §10, line 787). Yet success criterion 1 and §10 (lines 63 and 780) promise a no-video, motion-only run, which cannot use an encoder. Defer encoder dependency validation until appearance is actually requested, or provide an explicit `encoder.kind: none` for that mode. Test a minimal installation with no post-encoder extra.

8. **[Medium] The ledger does not account for all position edits.** The goal asks for a ledger of every edit (§1, line 42), but fill is explicitly event-free (§3, line 200), and optional smoothing overwrites observed boxes (§6.4, line 525). The header's row counts and smoothing flag do not identify which rows changed or their previous positions, so the audit cannot sample interpolation/smoothing errors and a reader cannot reconstruct an individual edit from the ledger. Record per-gap fill spans and per-track smoothing provenance, or narrow the ledger contract and provide a separate position-edit record.

These are static design and source checks; implementation tests were not run.
