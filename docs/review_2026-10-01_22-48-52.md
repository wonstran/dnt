## Comment

1. **[P1] Finish validating readable feature caches against the encoder.** The response says comment 3 is fixed, but `_well_formed` (plan lines 1464–1476) accepts any positive embedding width and checks finiteness before the load path casts values to `float32` (lines 1533–1552). A readable archive with the correct key and `emb.shape == (N, 1)` is accepted for a 384-dimensional DINO encoder. A partial cache then mixes widths when missing samples are encoded, causing `FeatureStore.get` or `save` to raise; a complete cache can silently score with the wrong vectors. Likewise, finite `float64` values larger than `float32` can become infinity on load. Pass the current `encoder.dim` to cache validation, reject rows with the wrong width, and verify finiteness after conversion to the stored dtype. Add both cases to Task 4 or Task 7 tests. This is the remaining part of the damaged-cache guarantee from the previous review.
