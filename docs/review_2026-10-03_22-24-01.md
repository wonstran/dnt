# Review of track dedup implementation plan

Reviewed: 2026-10-03 22:24:01 EDT  
Plan: [2026-10-03-track-dedup.md](superpowers/plans/2026-10-03-track-dedup.md)  
Spec: [2026-10-03-track-dedup-design.md](superpowers/specs/2026-10-03-track-dedup-design.md) (rev. 4)

The plan follows the revised design, including the documented change that AUTO_REJECT is not a cannot-link constraint. I found two reproducible test failures and three validation gaps. Resolve these before executing the plan so failing checks do not encourage weakening the intended behavior.

1. **[P2] Task 5, `test_an_applied_merge_drops_the_lower_score_rows_and_reports_them`: the fixture must be rejected by the supplied implementation.** Track 1 is observed on frames 0–19 and track 2 on 10–29. Within their overlap, both have ten observations and all ten are shared, so `co_occupancy = 1` and `shared = 10`. `_dense` blocks the hand-made accepted edge, correctly under the design. Executing the plan snippets in a scratch harness produced 40 unchanged rows, `applied=False`, and `skipped_reason="conflict"`, rather than the expected 30 rows and ten deletions. Use an interleaved fixture with a small shared fraction for the stage-level row-choice test, preserving explicit scores and deletion assertions. The fully co-observed case belongs in the conflict tests; the unrestricted row-choice primitive already has its own Task 3 tests. Do not bypass the safety check to make this fixture pass.

2. **[P2] Task 7, `test_an_accepted_merge_protects_its_representative_from_the_orphan_drop`: four rows is not the final pipeline result with fill enabled.** The merged observations are at frames 0, 10, 20 and 30, and `_Stages.run` subsequently calls fill. With the current defaults at 20 fps, those gaps are filled, yielding 31 rows; I reproduced that result with the proposed merge primitive and the existing `fill_stage`. The assertion `len(out) == 4` therefore fails after correct integration. Disable fill in the orphan-isolation fixture, or assert four observed rows plus the expected filled rows. Keep the orphan-protection assertion separate from interpolation behavior.

3. **[P2] Task 9: the real-data regression does not exercise the pipeline that motivated the feature.** `_run` reads raw rows and directly calls `propose_merges`, the router, and `apply_merges`. It never runs switch, screen, the new stage hand-off, link, orphan, fill, final renumbering, or video-backed appearance. This repeats the prototype's stage-only check and cannot establish spec criterion 1's P3-style output. Retain it as a focused calibration regression, but add a data-dependent run through `TrackRefiner.refine` with the relevant clip configuration and video/appearance inputs. Assert the three raw identities resolve to one output identity, inspect the resulting observed/fill rows and deletion accounting, and keep the negative pairs apart. If the data-dependent end-to-end run cannot execute in the review environment, report it as unverified rather than counting the raw-stage test as full criterion coverage.

4. **[P2] Tasks 7–8: the tests do not exercise a merge representative subsequently being absorbed by link.** `test_absorbed_ids_compose_across_dedup_and_link` merges 2 into 1 and links 3 into 1, so both mappings already point at the final survivor. It would pass even if `_absorb` only updated the map without composing old destinations. Task 8's pending-card test supplies a map that is already resolved, so it tests the consumer only. Add the requested two-hop integration case: A merges into B, B links into an earlier C, and a pending A/D MERGE survives. Assert the produced header resolves A to C and the actual card/snippet includes C's output ID. Include the carried representative and pending sets in the assertions so orphan protection also survives that second absorption.

5. **[P2] Task 6 and the self-review: the claimed downstream evidence exclusion is not tested.** `test_dedup_lineage.py` checks descriptors, embedding requests, legacy LINK lineage, orphan lineage and FILL lineage, but never constructs an `EvidenceBuilder` or checks its selected frames. The self-review maps all of spec test 18 to Task 6, although that test explicitly requires a later LINK's evidence to exclude the discarded raw observation. Add the recording-provider/interior-deletion case's evidence assertion using a real downstream event and an evidence builder initialized from the original raw table, where the deleted observation still exists. Check that `(122, 20)` is absent from the evidence tiles and any own-track context box lookup; this demonstrates that the propagated split spans, rather than deleting the raw source, enforce exclusion.
