# Review of P2 appearance encoders plan

Reviewed: 2026-10-01 22:30 EDT  
Plan: [2026-10-01-track-refinement-p2-appearance.md](superpowers/plans/2026-10-01-track-refinement-p2-appearance.md)  
Design: [2026-09-27-track-refinement-design.md](superpowers/specs/2026-09-27-track-refinement-design.md)

## Comments

1. **[P1] Identify the actual DINO weights in the feature key.** `DinoEncoder` sets `weights_sha = None` whenever `encoder.weights` is unset (plan lines 822–827), and `features_key` then keys the default Hub model only by its name (lines 1285–1295). If `facebook/dinov2-small` resolves to different weights later, a rerun reuses old embeddings despite a newly loaded model. This violates the design's weights-hash cache rule (§5.3). Pin a model revision and include its resolved commit or weight digest in the key, or hash the downloaded model artifact. Add a test in which the same model name resolves to different weights and the cache misses.

2. **[P1] Invalidate the memoized encoder when a local weights file changes.** `_encoder` memoizes on the weights *path* and config values (plan lines 2437–2444). A long-lived `TrackRefiner` can run once, have that file replaced in place, and run again with the same memoized model and `weights_sha`. The second run can even load the first run's feature cache because its key is unchanged. Include the current weights digest in the memo identity, or explicitly reload when it changes. Test two calls on one refiner with changed bytes at the same weights path.

3. **[P1] Treat structurally damaged feature archives as cache misses.** `FeatureStore.load` checks only that the three arrays have equal lengths before accepting an archive (plan lines 1349–1370). A valid `.npz` with the expected key but a one-dimensional, nonnumeric, or wrong-width `emb` array passes that check; later scoring or saving can then raise or use invalid values. A zero-dimensional `raw_id` array can raise at `len(ids)` outside the exception handler. Validate ranks, numeric dtypes, common embedding width, finite values, and ID/frame values before returning a store. Add malformed-but-readable `.npz` cases to Task 4's cache tests; the review focus promises that damaged caches never crash a run.

4. **[P1] Recheck candidate eligibility after moving a split.** `_candidates` enforces minimum clean data on both sides and non-maximum suppression before `_dense_rescore` runs, but `_relocate` can move a candidate by up to `sample_every` observed rows and the plan does not reapply either condition (plan lines 2026–2058 and 2081–2125). A boundary candidate can move to a cut with too little clean data on one side; two previously separated candidates can also move inside the NMS interval. Apply the side-length and NMS rules to the relocated cuts, and test a near-boundary cut and two converging candidates.

5. **[P1] Make the clipped-crop test agree with padded cropping.** Task 2's `test_crop_is_clipped_to_the_frame` asserts that the crop of `(-20, -10, 60, 40)` is at most 25 pixels high and 40 wide (plan lines 368–370). The proposed `crop_box` expands the box by 1.1 before clipping (lines 465–471), so its bounds on a 100×200 frame are `x=0..43`, `y=0..32`: the result is 43×32 and this test fails in Task 2's required green step. Assert the actual padded, clipped bounds, or change the crop rule if the unpadded intersection was intended.

Static review of the plan against the merged P1 code and design spec; no implementation tests were run.
