The comment is accepted. It is a gap in my fix for comment 3 of the previous review: `_well_formed` checked the shape of the archive but not that it fits the encoder in use, and it checked for finite values before the cast to `float32`. Both are real.

**Verification status.** As before, the revised plan has not been run end to end. The scratch dry run is still in progress and has been told about the changes. The new tests below are untested until it reports.

---

1. **P1: finish validating readable feature caches against the encoder.** **Accepted.**

   - **Wrong width.** `FeatureStore.load` now takes `dim`. The refiner passes `dim=encoder.dim` (Task 7). An archive whose embeddings have another width is a cache miss, even when its key matches. Without `dim` (callers that have no encoder) only a nonzero width is required.
   - **Finite after the cast.** The validator (renamed `_checked`, because it now returns the converted array) converts the embeddings to `float32` first, with overflow warnings suppressed, and tests finiteness on the converted values. A `float64` value such as `1e300` becomes `inf` on conversion, so that archive is a miss. The store keeps the converted `float32` rows, so what was validated is what is used.
   - **Mixed widths inside a store.** `FeatureStore.put` now raises `ValueError` for an embedding that is not a vector or whose width differs from the store's. This closes the other route the review describes: a loaded store of one width receiving freshly encoded rows of another, which used to fail only later, in `get` or `save`. The width is set by the first row, whether `put` or `load` supplies it.
   - **Tests.**
     - Task 4: `test_an_archive_of_the_wrong_embedding_width_is_a_miss_for_that_encoder` (width 2 with `dim=3` is a miss; `dim=2` and no `dim` load); `test_values_that_overflow_float32_are_a_miss` (and a `float64` archive that converts cleanly loads as `float32`); `test_put_rejects_an_embedding_of_another_width`.
     - Task 7: `test_a_cache_with_the_right_key_but_the_wrong_width_is_rebuilt` is an end-to-end case. It writes a readable archive with the correct cache key but 5 columns over a real cache, then reruns with a 3-wide encoder. The run recomputes, gives the same tracks, and leaves a valid cache behind.
   - **Interfaces.** The Task 4 interface block now documents `load(path, key, dim=None)` and the `put` check.
